# 联营扣点与结算

联营指商品由合作方提供、店里只代收代付并收取扣点。本仓的实现见 `saas-consign`。

## 扣点规则

- **合同默认扣点**：合作方的合同扣点，0–100%。
- **商品特例扣点**：某个商品可单独填写。为空表示跟合同。
- **生效扣点** = 商品特例（若有），否则合同默认。

对应代码：`CommissionMath.effectiveRate(productOverride, partnerDefault)`。

## 店抽成与应付

对一笔销售行，按**行净额**（已分摊满减、券、促销、积分之后的金额）计算：

- 店抽成 = 行净额 × 生效扣点 / 100
- 应付合作方 = 行净额 − 店抽成

对一个合作方的一段时间，汇总为一份结算单：

- 净销售额 = 各行净额之和
- 综合扣点 = Σ(行净额 × 扣点) / 净销售额
- 店抽成、应付按上面的公式汇总

对应代码：`ConsignSettlement.settleByPartner`。同一批次中如果某行缺少扣点，会直接抛出异常，避免静默按 0 结算。

## 示例

一天中，合作方 A 的两件商品分别卖出 100 元，商品 X 特例扣点 10%，合同默认 20%：

| 行 | 净额 | 扣点 | 店抽成 | 应付 |
|----|------|------|--------|------|
| X | 100.00 | 10% | 10.00 | 90.00 |
| Y | 100.00 | 20%（合同） | 20.00 | 80.00 |

综合扣点 15.00%，店抽成 30.00，应付 170.00。

## 改点与历史

- 改合同默认扣点或商品特例，只影响之后的销售；
- 已售出的行保留售出时的扣点快照，不因改点而变化；
- 每次改扣点写入变更记录，便于审计。

## 不在本仓范围内

联营结算的核销（生成应付、付款、冲销）与采购应付分开管理，属于完整产品的财务模块。
