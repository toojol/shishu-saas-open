# 条码秤 PLU 下发与称重条码

实现位于 `saas-device`。本文说明下发流程、PLU 文本帧和称重条码。

## 下发流程

秤在店内局域网。云端生成 PLU 数据，在线收银机领取任务后在内网写入秤：

- 秤不需要暴露到公网；
- 同一份数据可以派发给多台秤，并记录每台秤的同步结果。

## PLU 帧

示例协议通过 TCP（默认端口 4001）接收文本帧。

- 清空全部 PLU：`!0IA\r\n`，对应 `clearAllPlu()`。
- 下发一条 PLU：`!0V` 开头，后接 PLU 号、单价（单位为分，6 位补零）、若干固定字段，`B` 之后是品名的 GB2312 区位码，以 `CDE\r\n` 结束。对应 `buildPluFrame(plu, name, retailYuan)`。
- 品名最多取 12 个字符。
- PLU 号限制在 1–9999。
- 单价按 HALF_UP 换算为分。

固定字段（店号、部门、折扣、皮重等）按示例帧填写。改动前请对照设备手册，并先在测试秤上确认。

## TCP 下发示例（`TcpPluWriter`）

`TcpPluWriter.send(host, port, frames...)` 按顺序发送多帧，用于"先清空、再逐条下发"的流程。示例不包含重试与并发控制，生产环境请按门店网络情况自行加强。

## 称重条码（`ScaleBarcodeDecoder`）

默认版式为 13 位：

```
前缀 "21"（2 位）| PLU（5 位）| 中间段（6 位，重量或金额）| 校验位（1 位）
```

- 重量码：中间段 × 0.001 = 千克（默认系数）。
- 金额码：中间段直接表示金额，系数由配置决定。
- 校验方式：`STRICT` 要求校验位正确，不正确的码直接拒绝；`RELAX` 允许校验位不正确的码通过解析，结果中 `checksumOk` 为 `false`，由调用方决定是否采用。

`ScaleBarcodeDecoder.decode` 返回 PLU、原始中间段值、换算值与校验结果。PLU 为 0 的码视为无效。

校验位算法见 `BarcodeChecksum`，覆盖 EAN-8、UPC-A（12 位，前补 0 按 EAN-13 校验）与 EAN-13。

## 联调检查单

下面是联调时建议逐项确认的内容，实际结果以现场设备为准：

1. 秤的 IP 与端口（默认 4001）在收银机所在局域网内可达；
2. 先下发清空指令，确认秤上 PLU 被清空；
3. 下发一条测试 PLU，确认品名、单价显示正确；
4. 用带有该 PLU 的称重条码扫描，确认解析出的 PLU 与重量一致；
5. 品名含中文时，确认秤上显示没有乱码。
